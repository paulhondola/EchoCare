# iOS and watchOS Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A SwiftUI universal app (four roles) and a watchOS app in `ios/`, with the same behaviour as `android/`, signed with a free Personal Team, for the demo.

**Architecture:** One Xcode project with two app targets (`EchoCare` for iPhone and iPad, `EchoCareWatch` embedded in it) and one local Swift package (`Shared`: detectors and watch↔phone messages). The Android source is the behavioural spec: each Swift screen ports the Kotlin file of the same name, and each Kotlin unit test of pure logic is ported case for case with the same values.

**Tech Stack:** Swift 6, SwiftUI, Swift Testing, Xcode 27.2, HealthKit, CoreMotion, CoreLocation, WatchConnectivity, Firebase iOS SDK (FirebaseAuth only, Swift Package Manager).

**Spec:** `docs/superpowers/specs/2026-11-14-ios-port-design.md`

## Global Constraints

- Deployment targets: iOS 26.0, watchOS 26.0. `Shared` package also declares macOS 15 so `swift test` runs on the Mac.
- Bundle IDs: `ro.echocare.ios` (app), `ro.echocare.ios.watchkitapp` (watch). Set in `ios/Config/Base.xcconfig` as `BUNDLE_ID`, overridable in `Local.xcconfig`; the watch's is always `$(BUNDLE_ID).watchkitapp`.
- Signing: automatic, `DEVELOPMENT_TEAM` from git-ignored `ios/Config/Local.xcconfig`. Nothing team- or person-specific is committed.
- Build settings that mirror Android's `BuildConfig`: `API_URL` (default `https://echocare-api-staging.up.railway.app`, every route under `/api/`), `REREAD_SECONDS` (default 30), `REAL_SMS` (default `NO`; `NO` sets `isAppVerificationDisabledForTesting`). Read at runtime from Info.plist keys `EchoCareAPIURL`, `EchoCareRereadSeconds`, `EchoCareRealSMS`. In xcconfig write URLs as `https:/$()/…` (a bare `//` starts a comment).
- Demo timings: Debug builds are demo builds (Swift flag `DEMO`), Release uses production values: pulse hold 15 s / 60 s, inactivity 60 s / 4 h, „Sunteți bine?” timeout 15 s / 120 s, check-in every 1 min / 15 min, accelerometer 50 Hz, moving window 30 s.
- All user-facing text in Romanian, copied from `android/app/src/main/res/values/strings.xml` and the Wear OS screens, in `Localizable.xcstrings` with the Android keys. Code, comments, docs in English, citing spec IDs as the Android code does.
- No change to `android/`, `backend/`, `dashboard/` or any API contract. No push: no APNs entitlement, no `profile/push-tokens` calls.
- The watch never calls FastAPI (G5); every request goes through the iPhone app.
- Signer: Alex's Mac and Personal Team (design, The demo setup). `ro.echocare.ios` and `ro.echocare.ios.watchkitapp` are registered to that team.
- Simulator tests need the iOS 27.2 simulator runtime (`xcodebuild -downloadPlatform iOS`); the watchOS 27.2 runtime is installed.
- Never stage the untracked `fisa-medicala-*.pdf` at the repository root, or any other file outside the task's list: `git add` named paths only, never `git add -A` or `git add .`.
- Device installs from the command line: `xcodebuild build … -destination 'id=<udid>' -allowProvisioningUpdates -allowProvisioningDeviceRegistration`, then `xcrun devicectl device install app --device <udid> <path>.app` (the watch app goes to the watch's own UDID); `xcrun devicectl device copy from --domain-type appDataContainer` pulls a log file back. `xcrun devicectl list devices` gives the UDIDs.

## Review Focus

1. **Watch and phone out of reach mid-event:** an event raised while the iPhone is asleep or away must still arrive once and only once after it comes back. Test: Task 7 `EventQueueTests` (survives a restart, ack removes only that id) and Task 8 `relayAcksOnlyAfterAccepted`.
2. **Firebase token expiry during the demo:** a request made after the ID token expired must retry once with a fresh token, not show an error. Test: Task 4 `retriesOnceOn401WithFreshToken`.
3. **Backend sends a role or status value this build doesn't know:** decoding must drop or tolerate it, not fail the whole screen. Test: Task 4 `decodesUnknownRoleAndExtraFields`, Task 5 `unknownRolesAreDropped`.
4. **Workout session ends unexpectedly** (watch taken off, session ended by the system): monitoring stops visibly and check-ins stop, so UC-13 marks the watch offline instead of the app pretending to monitor. Test: Task 7 `monitorStateFollowsSessionEnd`.
5. **Senior taps Da/Nu after the prompt already timed out**, or a second anomaly arrives while the prompt is showing: exactly one event per prompt, as on Wear OS. Test: Task 7 `promptResolvesOnce`.
