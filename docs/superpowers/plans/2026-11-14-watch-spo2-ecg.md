# Blood oxygen and ECG from Apple Health Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The senior's iPhone reads blood oxygen and ECG recordings from Apple Health, FastAPI keeps them 24 hours, and the dashboard's watch card shows the latest SpO2, a 24-hour SpO2 line and the latest ECG with Apple's verdict and a 10 s trace.

**Architecture:** A new `health_readings` table owned by `seniors`, written by `POST /me/health-readings` and read by `GET /seniors/{id}/watch/health`. On iOS, a `HealthSync` class runs anchored HealthKit queries on the senior's phone and posts each sample; pure conversion functions shorten the ECG to 128 Hz. The dashboard polls the new read and draws it inside `WatchHealth.svelte` with the existing `sparkline`.

**Tech Stack:** FastAPI, SQLAlchemy 2 async, Alembic, Pydantic v2, pytest; Swift 6, HealthKit, Swift Testing; Svelte 5, TypeScript, Vite+ test.

**Spec:** [docs/superpowers/specs/2026-11-14-watch-spo2-ecg-design.md](../specs/2026-11-14-watch-spo2-ecg-design.md)

## Global Constraints

- Work on branch `watch-spo2-ecg`, cut from `main`. Never merge, push to `main`, or open a PR without Alex asking. ADR-008 must be agreed first; the migration freezes on merge.
- Commit with the hooks on (`lefthook`); never `--no-verify`.
- API and migration only add: new endpoint, new table, new optional export field. `WatchView`, `GET /seniors/{id}/watch` and Android's `Api.kt` don't change.
- Only `seniors` writes `health_readings` (ADR-005); `export` and `erasure` call `seniors`' functions.
- Retention: 24 hours, `READINGS_KEPT` in `backend/app/seniors/service.py`.
- Readings never create an event, call, code change or push.
- User-facing text is Romanian; code, comments and docs English. Cite spec IDs in comments (`04 §3`, `ADR-008`, `design 2026-11-14`).
- `kind` values: `spo2`, `ecg`. `ecg_classification` values: `sinus_rhythm`, `atrial_fibrillation`, `inconclusive_low_heart_rate`, `inconclusive_high_heart_rate`, `inconclusive_poor_reading`, `inconclusive_other`, `unrecognized`.
- Bounds: `spo2` 50–100; `ecg_heart_rate` 0–300; `ecg_trace` at most 1,280 ints, each -10,000 to 10,000 (µV); `ecg_trace_hz` 1–512.
- Romanian verdict labels: `sinus_rhythm` „Ritm sinusal”, `atrial_fibrillation` „Fibrilație atrială”, `inconclusive_low_heart_rate` „Neconcludent: puls scăzut”, `inconclusive_high_heart_rate` „Neconcludent: puls ridicat”, `inconclusive_poor_reading` „Neconcludent: citire slabă”, `inconclusive_other` „Neconcludent”, `unrecognized` „Neclasificat”.
- HealthKit, ECG voltages and Watch → iPhone sync can only be checked on a real device; say so in each iOS task's report.

## Review Focus

1. **The same HealthKit sample from two seniors** (one demo iPhone moved between seeded seniors): each senior stores their own copy. Test in Task 1: `test_the_same_id_for_two_seniors_is_stored_twice`.
2. **A re-send after every app launch:** the phone re-sends the last 24 hours each time; the second send must answer 204 and change nothing. Test in Task 1: `test_a_duplicate_is_204_and_stored_once`.
3. **A watch clock in the future, or a backfilled sample older than 24 h:** future → stored at arrival time; older than 24 h → 204, not stored. Tests in Task 1: `test_a_future_time_is_stored_as_arrival`, `test_older_than_a_day_is_not_stored`.
4. **An ECG with no voltages or a sampling rate other than 512 Hz:** the phone sends no trace, or computes the factor from the rate, never assumes 512. Tests in Task 5: `shortensAnyRate`, `emptyVoltagesGiveNoTrace`.
5. **A verdict string the dashboard doesn't know** (Apple adds one later): shown as it is, not blank. Test in Task 6: `"an unknown verdict shows as it is"`.
